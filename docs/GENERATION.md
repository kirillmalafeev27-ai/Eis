# Как устроена генерация вопросов

Движок вопросов и ИИ-механика перенесены из Morskoy. Задания сочиняет модель на сервере игры,
но не по запросу «сгенерируй 10 заданий по теме X»: промпт собирается из модулей с инструкциями
для ИИ, а ответ модели проверяет код. В игру попадают только задания, прошедшие проверку.

```
игрок выбирает темы ──► AiQuestionProvider ──POST /api/generate-questions──► сервер
                         (очереди по темам)                                    │
        панель вопроса ◄── вопрос серии ◄── задания {format,text,display,…} ◄──┤
                                                                               ▼
                       промпт = уровень + правила темы + форматы + правила качества
                       модель (AI Tunnel) → текст с ключом ответов → разбор → проверка
```

## Инструкции для ИИ — `server/generation/`

Тексты правил совпадают с Morskoy дословно (тест сверяет, что у каждой темы клиента есть правила;
промпт для одинаковых входных данных получается тот же байт в байт).

| Модуль                  | В Morskoy                    | За что отвечает                                                                        |
| ----------------------- | ---------------------------- | -------------------------------------------------------------------------------------- |
| `grammarRules.ts`       | `lib/grammar-rules.js`       | 47 грамматических тем: правило, дизайн задания, форматы, дистракторы, запреты          |
| `exerciseFormats.ts`    | `lib/exercise-formats.js`    | каталог из 9 форматов заданий с разобранными примерами                                 |
| `qualityRules.ts`       | `lib/quality-rules.js`       | общие правила: субстанция вариантов, качество дистракторов, список брака, самопроверка |
| `exercisePrompt.ts`     | `lib/exercise-prompt.js`     | уровни A1–C1 и сборка итогового промпта                                                |
| `exerciseValidation.ts` | `lib/exercise-validation.js` | проверка ответа модели: что промпт не гарантирует — проверяет код                      |
| `textFormat.ts`         | `quiz-generation.js`         | разбор текстового ответа: блок `AUFGABEN` и отдельный ключ `LÖSUNGEN`                  |
| `audioTasks.ts`         | `quiz-generation.js`         | задания на аудирование: промпт, разбор, запасные дистракторы                           |

## Главная проблема, которую решает система

Типовой плохой вопрос:

```
Er versucht, den Bahnhof ___ finden.
A) zu     B) –     C) zum     D) um zu
```

Это не упражнение. Кто знает конструкцию, узнаёт ответ мгновенно; кто не знает — гадает из
четырёх. Проверяется не владение `Infinitiv mit zu`, а узнавание частицы.

Правильная версия той же темы:

```
Sein Zug fährt um sechs. (vorhaben – früh aufstehen)
A) Er hat vor, morgen früh aufzustehen.      ← верно
B) Er hat vor, morgen früh zu aufstehen.
C) Er hat vor, morgen früh aufstehen zu.
D) Er hat vor, morgen früh aufstehen.
```

Варианты — целые предложения из одного и того же материала, различаются только положением `zu`.
Угадать по длине или по «единственному осмысленному варианту» нельзя.

## Правило субстанции

Формулируется в `qualityRules.ts`: **вариант ответа должен содержать всю целевую структуру,
а не один элемент из неё.**

| Тема                                      | Что должно быть в варианте                        | Что запрещено           |
| ----------------------------------------- | ------------------------------------------------- | ----------------------- |
| Infinitiv mit zu                          | вся инфинитивная группа или предложение целиком   | `zu / – / zum / um zu`  |
| Падежи, артикли, склонение прилагательных | вся именная группа: `ihrer neuen Kollegin`        | `dem / den / der / des` |
| Perfekt, Passiv, Futur, модальные         | весь глагольный комплекс, лучше двойным пропуском | одно причастие          |
| Порядок слов, придаточные, рамка          | всегда целые предложения                          | обрывки                 |

Единственное исключение — когда целевое явление действительно одно слово: выбор союза
(`als / wenn / wann`), значение модального глагола, предлог при фиксированном управлении. Тогда
решение должен нести контекст (мини-диалог или однозначные слова-сигналы), а предложение — быть
не короче восьми слов.

## Форматы заданий — «формат квиза»

Задание в формате генератора — это инструкция по-русски (`text`), немецкий материал (`display`)
и ровно четыре варианта (`options`, `correct`). Для каждой темы в `grammarRules.ts` перечислено,
какие форматы подходят; в промпт попадают только они, вместе с разобранными примерами.

| id                | Формат                                              | Что даёт                                     |
| ----------------- | --------------------------------------------------- | -------------------------------------------- |
| `satzvarianten`   | выбор из четырёх целых предложений                  | снимает угадывание по длине                  |
| `umformung`       | преобразование (актив → пассив, презенс → претерит) | проверяет продуктивное владение              |
| `verbindung`      | соединить два предложения в одно                    | падеж и порядок слов сразу                   |
| `fehlerkorrektur` | найти и исправить одну ошибку                       | вариант «не исправлено» — сильный дистрактор |
| `dialog`          | мини-диалог, решает контекст                        | честный способ проверять значение            |
| `mehrfachluecke`  | два пропуска, матрица 2 × 2                         | половинное знание видно в статистике         |
| `wortstellung`    | собрать предложение из частей                       | целые предложения в вариантах                |
| `bedeutung`       | минимальная пара, все варианты грамматичны          | проверяет понимание, а не форму              |
| `luecke`          | классический пропуск, но со всей структурой         | базовый формат для падежей и форм            |

В блоке из 10 заданий нужно минимум 4 разных формата, не больше 4 заданий одного формата и
минимум 2 задания из сложных форматов (`umformung`, `verbindung`, `fehlerkorrektur`, `bedeutung`).

В игре задание показывается так: инструкция мелко над жёлтой бумажкой, немецкий материал на ней
(реплики диалога — с новой строки), варианты-предложения — столбиком во всю ширину с текстом по
левому краю, короткие варианты — сеткой 2 × 2. Шрифт подбирается сразу для всего задания; если на
маленьком экране не встаёт и на минимуме, лист прокручивается (см. `DECISIONS.md`).

## Что проверяет код, а не промпт

`exerciseValidation.ts` отбраковывает то, что модель всё равно иногда присылает:

- не ровно 4 варианта, пустые или повторяющиеся варианты;
- пропуск `___` внутри варианта ответа;
- оборванное предложение (заканчивается на `...`);
- расхождение номера правильного ответа и его текста — модель обязана продублировать ответ
  дословно, и это сверяется;
- **нарушение правила субстанции**: если все четыре варианта короче минимума для темы, задание
  отклоняется;
- варианты, отличающиеся по длине более чем в 5 раз;
- дубли внутри блока и повтор уже выданных заданий;
- перекос по форматам: лишние задания одного формата уходят в конец очереди.

Причины отбраковки пишутся в лог сервера (по-немецки, как в Morskoy) — по ним видно, на чём
спотыкается модель:

```
[Infinitiv mit zu B1] 8/12 Aufgaben übernommen; aussortiert: Füllwort-Optionen: Thema verlangt mindestens 3 Wörter je Option; doppelte Optionen
```

Сервер просит на 4 задания больше, чем нужно, — с запасом на брак; лишние задания ждут в пуле по
ключу «уровень × тема × лексика × Wortstellung» и уходят следующему запросу без обращения к модели.

## Уровни

`exercisePrompt.ts` разворачивает «уровень A2» в конкретные ограничения: длина предложения,
разрешённые и запрещённые структуры, пласт лексики, замечание о подходящих форматах. Без этого
«A2» для модели — пустой ярлык.

## Клиент: темы, очереди, запасной путь

- **Выбор тем** (`src/ui/screens/QuizScreen.ts`, кнопка «Вопросы» в меню) — шаги меню Morskoy в
  одной карточке: уровень A1–C1, лексическая тема, до пяти грамматических тем, слот
  Wortstellung (порядок слов на материале первой темы) и аудирование. Выбор хранится в
  `localStorage` (`ice:quiz`). При первом «Играть», если на сервере есть ключ генерации, выбор
  тем открывается сам.
- **`AiQuestionProvider`** (`src/shared/questions/`) — движок `QuestionManager` из Morskoy под
  интерфейс `QuestionProvider` серии: блок по 10 заданий на тему, темы чередуются, следующий блок
  запрашивается заранее (когда в очереди остаётся 5), уже показанные задания уходят в `exclude`,
  варианты перемешиваются при каждом показе, неверно решённое задание возвращается через
  4–6 вопросов (12.3).
- **Ожидание и запасной путь.** Первый вопрос после выбора тем раунд ждёт до 45 с — в интро,
  когда всё стоит, с подписью «Готовлю вопросы…». Если генерации нет (нет ключа, сервер
  недоступен, игра раздаётся как статика) или модель не ответила — вопросы берутся из встроенного
  банка `bank.de.json`, игра не встаёт.
- **Аудирование.** Фраза звучит сама, когда вопрос становится активным (если звук не выключен);
  кнопка «Слушать» повторяет её. Озвучка — `/api/tts` (ElevenLabs), без ключа — голос браузера.

## Сложность

Задания генератора читаются в разы дольше слов банка, их время сильнее разбросано, а верных
ответов меньше. Поэтому темп ученика для них считается отдельно (на каждый уровень A1–C1), с
поправкой на разброс и запасом ×1.18, а после ошибки верный вариант виден 1,8 с. Как это
подобрано симуляцией и какие получились проценты побед — в `DECISIONS.md`, раздел «Сложность с
заданиями генератора».

## API

| Метод  | Путь                            | Что делает                                                                                                                             |
| ------ | ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`  | `/healthz`, `/health`           | `{"ok":true}` — проверка здоровья, не зависит от ключей                                                                                |
| `GET`  | `/api/quiz/status`              | настроены ли генерация и озвучка, список моделей                                                                                       |
| `POST` | `/api/generate-questions`       | `{level, grammarTopic, lexicalTopic?, isWortstellung?, count?, exclude?}` → `{questions: [{format, text, display, options, correct}]}` |
| `POST` | `/api/generate-audio-questions` | `{level, lexicalTopic?, count?, exclude?}` → `{questions: [{mode:'audio', text, display, audioText, options, correct}]}`               |
| `POST` | `/api/tts`                      | `{text}` → `audio/mpeg`                                                                                                                |

Тема должна быть из каталога (`resolveTopic`), иначе `400` — API не превращается в бесплатный
доступ к модели с произвольным текстом в промпте. Без ключа генерация отвечает `503`, и клиент
сразу переключается на встроенный банк.

## Как добавить тему

1. Добавить название в `GRAMMAR_GROUPS` в `src/shared/questions/topics.ts`.
2. Добавить запись в `GRAMMAR_RULES` в `server/generation/grammarRules.ts` с полями `rule`,
   `design`, `formats`, `traps`, `avoid` — и ту же запись в Morskoy, чтобы правила не разошлись.
3. Если целевая структура больше одного слова — внести тему в `PHRASE_TOPICS` или
   `SENTENCE_TOPICS` в `server/generation/exerciseValidation.ts`.
4. `npm test` — тест проверяет, что у каждой темы клиента есть правила и что все указанные
   форматы существуют.

Если клиент присылает название в ASCII-транслитерации (`Praeteritum`, `Relativsaetze`), оно всё
равно найдётся: `resolveTopic` нормализует умлауты и знает список синонимов.
